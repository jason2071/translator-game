# 🛡️ Game Safety — how we keep games unbroken

One principle: **the game must stay the same game — only its language changes.**
Every rule below exists because its violation costs a real user a broken game
(see [[cases]]; e.g.
[[2026-09-18-renpy-empty-screen-decompile]] broke rules 3 and 5). Cases record
incidents; this file is the standing policy they are measured against.

## The rules

1. **Language and font scope only.** We may change: translated text, `tl/<lang>/`
   overlays, fonts we add, font/language wiring (`zzz_translator.rpy`), and the
   minimum style tweaks the target script needs to render (e.g. Thai
   `language = "anywhere"`). We may never change: gameplay logic, values,
   configs beyond language, assets other than added fonts, saves. When a
   change is arguably "nice to have" but not language/font-related — it's out
   of scope, full stop. This binds what the *app* writes through its extract /
   export paths; mods a user builds by hand outside the app are their own
   business.

2. **Additive by default; in-place only through pointers.** A new file with a
   new name beats editing an existing one. When an engine requires in-place
   edits (RPGMaker MV/MZ JSON, Tyrano/KiriKiri `.ks` splices), the write goes
   through the engine's pointer, preserves round-trip identity, and happens
   only after the original bytes are snapshotted to `.rpgtl/source/`.

3. **Never shadow or delete an original.** A file we write must not take
   precedence over a file the game shipped — the `.rpy`-shadowing-`.rpyc`
   incident. If shadowing is required (decompiling a compiled-only game), the
   written file must be validated as far as is feasible: repair the patterns
   we know a decompiler gets wrong, parse-check whatever the format lets us
   parse. A third-party tool's exit code is not validation: unrpyc exits 0 on
   uncompilable output.

4. **Everything we add is marked, listed, removable.** Files we create carry a
   header comment saying so + how to remove them; our assets live in dedicated
   paths (`fonts/tl_font.ttf`, `fonts/tl_icons.ttf`, `tl/<lang>/`,
   `zzz_translator.rpy`). Bundled fonts must carry a license that permits
   redistribution — they ship inside users' games and exported mods. In-place
   engines are undone by `project::restore_original` (snapshots +
   `font-restore/added.txt`); additive overlays are undone by deleting those
   paths — the full footprint must always be enumerable.

5. **Validate what we wrote before declaring success.** The app, on every
   export: parse-check everything it wrote where it's cheap (strict JSON for
   MV/MZ and Hendrix, `.po`/`.csv` for Godot); Ren'Py `tl/` skeletons are
   generated by the game's own launcher, so they're trusted. Us, whenever we
   change extract / inject / decompile code or close a case: launch the game
   and confirm `log.txt` reaches "Loading script took …" with no `errors.txt`
   rewrite — and when our writes touched script files, load a pre-existing
   save too (a subtly divergent script can boot fine and still break saves).

6. **Diagnose on a copy, never the live game.** Tools mutate beside their
   input (unrpyc writes `.rpy` next to the `.rpyc`). Copy the file to a
   sandbox first — the recipe is in
   [[2026-09-18-renpy-empty-screen-decompile]].

7. **Bytes we don't own stay identical.** Encoding (Shift-JIS, UTF-16, BOM),
   line endings, key order — unchanged outside the translated span. Never
   "upgrade" an encoding while writing.

8. **Player data is sacred.** Saves, settings, unlocks, gallery progress:
   read-only, always.

9. **Exceptions must be listed here.** If a rule must be broken, the exception
   is documented in the next section with its mitigation — an undocumented
   exception is a bug.
10. **Writes into the game are atomic.** A live game file is replaced by
    write-temp-then-rename, never rewritten in place, so a crash or full disk
    can't leave a half-written file behind. (Engines adopt this incrementally;
    gaps are listed as exceptions below.)
11. **Export refuses to start while the game holds our targets.** Before the
    first write, probe the files we're about to touch; if any is locked (the
    game is running), abort with "close the game first" instead of failing
    half-way through.

## Current exceptions (audited)

- **Ren'Py decompile-on-import** (rule 3): compiled-only games get `.rpy`
  written beside their `.rpyc` because extraction needs source. Mitigated:
  only the missing sources are decompiled (never a whole-dir clobber), the
  output is post-validated — repaired, or deleted when the render is broken so
  the game falls back to its own `.rpyc` — and recorded in
  `.rpgtl/decompiled.txt` for restore. See
  [[2026-09-18-renpy-empty-screen-decompile]] and
  [[2026-09-18-renpy-redecompile-clobber]].
- **Ren'Py in-place fallback inject** (rule 2): when no bundled launcher is
  found, translation is injected in place. Mitigation: snapshot + restore,
  same as other in-place engines.
- **Engine inject writes are not yet atomic** (rule 10): only the export
  reset-copy and the decompile post-pass go through `engine::write_atomic`;
  the per-engine `inject` sites still write directly. Adopt incrementally.
